# 计算机网络基础资料

## 分层体系结构

计算机网络通常采用分层体系结构来降低系统复杂度。OSI 参考模型包含物理层、数据链路层、网络层、传输层、会话层、表示层和应用层。实际互联网更常使用 TCP/IP 四层模型，即网络接口层、网际层、传输层和应用层。分层的意义在于每一层只关注本层职责，并通过接口向上层提供服务。这样既方便协议替换，也便于定位网络故障。

## TCP 与 UDP

TCP 是面向连接的可靠传输协议。通信双方在传输数据前需要通过三次握手建立连接，传输过程中使用序号、确认应答、重传、流量控制和拥塞控制保证可靠性。TCP 适合文件传输、网页访问、邮件发送等对可靠性要求高的场景。

UDP 是无连接传输协议。它不保证可靠交付，也不维护连接状态，因此协议开销小、时延低。UDP 常用于 DNS 查询、实时音视频、在线游戏等更关注实时性的场景。应用如果使用 UDP 并需要可靠性，需要在应用层自行设计确认、重传或纠错机制。

## IP 地址与路由

IP 地址用于标识网络中的主机或接口。IPv4 地址长度为 32 位，通常写成点分十进制形式。路由器根据路由表选择下一跳，把数据报逐步转发到目标网络。CIDR 使用“地址/前缀长度”的方式表示网络范围，例如 192.168.1.0/24 表示前 24 位是网络前缀。

## HTTP 与 HTTPS

HTTP 是应用层协议，采用请求-响应模型。浏览器向服务器发送请求，服务器返回状态码、响应头和响应体。HTTPS 在 HTTP 与 TCP 之间加入 TLS 加密层，用于提供身份认证、数据加密和完整性校验。HTTPS 可以降低窃听、篡改和中间人攻击风险，是 Web 服务的常规部署方式。

## DNS 解析

DNS 的作用是把域名解析为 IP 地址。客户端通常先查询本地缓存，再请求递归 DNS 服务器。递归服务器可能继续查询根域名服务器、顶级域名服务器和权威域名服务器，最终得到目标域名对应的地址记录。DNS 缓存可以减少重复查询，提高访问速度，但缓存过期时间也会影响域名变更生效速度。
