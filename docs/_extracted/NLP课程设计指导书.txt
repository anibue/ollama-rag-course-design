《Ollama 大模型部署与 NLP 应用》课程设计指导书
广东工业大学计算机学院
一、课程设计目的与说明
部署只是门槛，不是得分项。
Ollama 的安装和模型部署是完成本课程设计的基础条件，但仅完成部署不能获得及格分数。参考文档（DataWhale 动手学 Ollama：https://datawhalechina.github.io/handy-ollama/）中包含详细的安装步骤和代码示例，这些内容可以直接参考，但参考文档不能替代你的思考和设计。
本课程设计要求学生在完成模型部署的基础上，选择一个具体的 NLP 任务，分析任务需求，设计解决方案，实现系统并进行评测。仅仅"把文档里的示例跑一遍"是不够的——你需要说明：
• 为什么选择这个模型？
• 任务的目标是什么？输入输出是什么？
• 如何将大模型应用于这个任务？有哪些技术挑战？
• 效果如何？有哪些改进空间？
二、课程设计题目
基于 Ollama 的本地大模型部署与xxx应用开发
三、课程设计任务类型
以下任务类型，学生必须选择至少一项完成。
任务 A：RAG 应用开发（检索增强生成）
任务描述：利用本地部署的大模型，构建基于检索增强生成（RAG）的应用系统。
可选子任务（任选其一）：
A1 - 表格问答：上传结构化表格数据（CSV/Excel），用户可以用自然语言提问，系统基于表格内容给出准确回答。
输入：一段自然语言问题（如"2023年营收最高的公司是哪家？"）
输出：基于表格内容生成的准确回答
A2 - 专业文档问答：上传领域文档（教材、论文、技术文档等），构建知识库，用户提问时系统从文档中检索相关内容并生成答案。
输入：一段专业领域的问题（如"什么是 Transformer 架构？"）
输出：从知识库中检索相关内容并生成的回答
技术要点：文档解析与文本分割、向量嵌入（Embedding）与相似度检索、检索结果与生成模型的结合。
参考文档：handy-ollama 第 7.3-7.7 节提供了 LangChain/LlamaIndex 搭建 RAG 的示例代码，可直接参考框架，但需自行完成数据准备、任务设计和效果评测。
任务 B：AI 生成内容检测
任务描述：构建文本分类系统，判断输入文本是否由大模型生成。
输入：一段文本（100字以上）
输出：判断结果（"AI 生成" / "人类创作"）及置信度
技术要点：可采用零样本分类（Zero-shot Classification）或设计特征工程结合传统机器学习。
任务 C：情感分析
任务描述：构建文本情感分析系统，判断输入文本的情感极性。
输入：一段文本（评论、社交媒体内容等）
输出：情感极性（"正面"/"负面"/"中性"）及置信度
技术要点：可采用零样本分类或提示词工程，支持批量分析和结果统计。
任务 D：跨模态文本生成
任务描述：利用多模态大模型完成图像描述生成任务。
可选子任务（任选其一）：
D1 - Image Captioning（图像描述）：输入一张图片，模型生成一段自然语言描述。
输入：一张图片 | 输出：一段描述图片内容的文字
D2 - Video Captioning（视频描述）：输入一个视频片段，模型生成视频内容的文字描述。
输入：一个短视频（可截取关键帧） | 输出：描述视频中发生的事件
技术要点：需要使用支持多模态的模型（如 LLaVA、Qwen-VL 等）。
四、课程设计难度档位
重要说明：完成 Ollama 部署和模型运行是所有档位的前置条件，不计入学业成绩。只有在此基础上完成 NLP 任务，才能获得相应分数。
各档位详细要求
基础档（60-69 分）要求：
1. Ollama 安装配置 + 模型部署
2. 选定一个任务类型（A/B/C/D），明确任务定义、输入输出
3. 完成基本的任务实现，能够运行并产生结果
4. 撰写报告，说明：任务背景与目标、技术方案、实现过程、测试结果（至少10条）、总结与反思
报告篇幅：正文不少于 3000 字，代码注释和图表不计入。
进阶层（70-79 分）要求：
在基础档基础上，增加：效果评测（至少30条样本，优先使用公开数据集）和技术分析。
提升档（80-89 分）要求：
在进阶层基础上，选择以下一项进行优化：Prompt Engineering / 模型组合 / RAG 优化。必须有明确的效果对比。
加分挑战（+10 分，最高可达 100 分）：
在提升档基础上，完成以下任一任务：LoRA 微调 / 公开评测 / 创新应用 / 模型对比。
五、课程设计步骤
1. 环境准备与模型部署：配置 Ollama 运行环境、选择并部署合适的模型、安装必要的依赖库
2. 任务分析：确定任务类型、明确输入输出、调研相关技术
3. 系统设计与实现：设计架构、开发核心功能、测试调优
4. 效果评测：设计指标、准备数据、运行评测、分析结果
5. 撰写报告：整理文档、撰写报告、准备答辩材料
六、报告撰写要求
报告结构（必须包含）：
1. 摘要（200-300字）：简述任务目标、方法、主要成果
2. 第一章 绪论：任务背景与意义、任务定义、技术路线概述
3. 第二章 环境配置与模型选择：Ollama 安装与配置、模型选择与理由
4. 第三章 系统设计与实现：系统架构设计、核心功能实现
5. 第四章 实验与评测：评测指标与测试数据、实验结果与分析（优先使用公开数据集）
6. 第五章 总结与展望
7. 参考文献（至少 10 篇，含参考文档）
8. 附录：核心代码、配置说明等
格式要求：A4 纸双面打印，正文宋体小四号，1.5 倍行距，代码等宽字体，图表清晰编号连续。
七、技术建议
模型选择参考：
推荐工具链：模型管理（Ollama）、RAG框架（LangChain、LlamaIndex）、向量数据库（ChromaDB、FAISS）、Web界面（Gradio、Streamlit）、微调工具（LLaMA-Factory、PEFT）
八、自愿答辩与冲击优秀
为什么报名答辩？
冲击 90+ 分的唯一途径：前三项（报告、方案、评测）满分 90 分，不答辩最高 89 分。完成加分任务并报名答辩者，有机会获得答辩加分，总分可达 90-100 分。
答辩规则：
• 答辩为自愿报名，不强制
• 不报名答辩者，课程设计最高得分 89 分
• 报名答辩者，答辩表现将获得 0-13 分的加分
• 答辩时间安排另行通知
报名方式：拟报名答辩者，请在提交课程设计报告时同步说明，具体安排见课程群后续通知。

• 本课程设计注重问题分析与解决方案设计，而非照抄文档
• 模型部署建议提前完成，避免影响任务实现进度
• 参考文档和代码必须标注来源，否则视为抄袭
