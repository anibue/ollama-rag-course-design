# 基于 Paper.md 论文的项目改进建议

> 结合项目现有架构（Ollama 本地 RAG + 混合检索 + JSON 索引 + scikit-learn），对 Paper.md 中 40 篇论文逐一提出可落地的改进方案。

---

## 一、RL 训练 RAG（论文 1–20）

### 检索策略优化类

| # | 论文 | 项目改进建议 |
|---|------|-------------|
| 1 | **R3-RAG** | 你的项目已有 `hybrid` 检索（向量+TF-IDF），可借鉴其"结果奖励+过程奖励"双信号思路，为检索片段引入**相关性二分类标注**（人工标注 50 条正负样本），训练一个轻量打分器对 Top-K 片段做二次过滤，替换现有的固定权重融合。 |
| 2 | **UR2** | 其"难度感知课程学习"思路可落地为：按 `eval_questions.csv` 中问题的检索命中率排序，**先在简单问题上调参**（权重、Top-K），再逐步扩展到难问题，建立分层调优流程，写入报告作为调参策略说明。 |
| 3 | **R-Search** | 其"多奖励信号"可简化借鉴：在 `rag_chain.py` 中增加**答案置信度自评**——让模型输出后额外回答"此答案是否充分"（是/否），置信度低时自动触发二次检索并合并结果，形成简单的自适应检索循环。 |


### 过程监督与推理增强类

| # | 论文 | 项目改进建议 |
|---|------|-------------|
| 5 | **ProRAG** | 其"过程监督"可落地为：在 Prompt 中要求模型**分步推理**（先列出相关事实→再推导→再回答），记录每步引用的片段编号，评测时检查推理链是否忠实于检索结果，增加"忠实度"指标。 |
| 7 | **ReasonRAG** | 其"MCTS+最短路径奖励"可简化为：在 `rag_chain.py` 中增加**检索深度控制**——如果第一次检索的答案覆盖度低于阈值 0.3，自动扩大 Top-K 或切换到纯 TF-IDF 模式重试，形成两阶段检索。 |
| 8 | **ReaLM-Retrieve** | 其"步级不确定性检测"可落地：在生成过程中让模型在每个推理步骤输出**不确定标记**（如 `[不确定]`），遇到标记时触发检索补充，实现按需检索而非一次全检索。 |
| 16 | **Self-Correcting RAG** | 其"NLI 验证忠实性"可简化为：生成答案后用**NLI 模型**（如 `cross-encoder/nli-deberta-v3-small`）检查答案中的每个声明是否被检索片段蕴含，输出忠实度分数，加入评测指标。 |


### 检索控制与效率类

| # | 论文 | 项目改进建议 |
|---|------|-------------|
| 9 | **GRIP** | 其"token 级检索控制"启发：在 Prompt 中设计**检索决策指令**——让模型先判断"是否需要检索"，如果模型回答"不需要"则直接用参数知识回答，否则触发检索，减少不必要的检索调用。 |
| 13 | **A-RAG** | 其"三级检索接口"可落地为：在 `config.py` 中增加**三种检索模式**配置（关键词→语义→全文阅读），用户可通过 Streamlit 页面切换，对比不同粒度检索的效果。 |
| 18 | **SEAKR** | 其"内部状态不确定性"可简化为：用**答案长度和重复率**作为不确定性的代理指标——短答案或高重复答案触发二次检索，在 `rag_chain.py` 中实现。 |
| 19 | **SIM-RAG** | 其"自我练习生成过程监督数据"可落地：用当前系统对 100 个问题生成检索+回答轨迹，人工标注哪些检索是必要的，训练一个**轻量检索触发分类器**（sklearn LogisticRegression 即可）。 |


### 多智能体与图增强类

| # | 论文 | 项目改进建议 |
|---|------|-------------|
| 10 | **GraphRAG-R1** | 其"图+文本混合检索"可简化为：用 `spacy` 或简单规则从知识库文档中**抽取实体关系三元组**，构建小型知识图谱 JSON，检索时同时查向量和查图谱，对比纯向量的效果。 |
| 11 | **MMOA-RAG** | 其"多智能体协作"可落地为：将 RAG 拆成**检索 Agent + 生成 Agent + 验证 Agent**，验证 Agent 检查生成答案是否引用了检索片段，不通过则重新生成，用 `src/` 中新增模块实现。 |
| 12 | **MAO-ARAG** | 其"动态工作流编排"启发：在 Streamlit 页面增加**工作流选择器**（直接回答 / 检索回答 / 多轮检索），让用户对比不同复杂度工作流的耗时和质量。 |
| 15 | **PyRAG** | 其"Python 程序合成"可落地为：对多跳问题（如"A 和 B 的关系是什么？"），让模型先生成**检索计划**（先查 A→再查 B→再综合），分步执行并合并结果。 |

## 二、LLaMA + RAG（论文 1–20）

### 方法类

| # | 论文 | 项目改进建议 |
|---|------|-------------|
| 1 | **Self-RAG** | 其"reflection token"思路可落地：在 Prompt 中增加**反思标记指令**——要求模型在回答前先输出 `[检索:是/否]`、`[相关:是/否]`、`[有用:是/否]`，统计反思准确率作为评测指标。 |
| 2 | **RankRAG** | 其"统一排序与生成"启发：在 `build_kb.py` 中增加**片段质量评分**（基于片段长度、信息密度），在检索时用该分数加权，替代纯相似度排序。 |
| 3 | **RA-DIT** | 其"双指令微调"思路可落地：虽然无法微调 7B 模型，但可以**分别优化检索参数和生成 Prompt**——用网格搜索找最优权重组合（0.3-0.7 范围），同时优化 Prompt 模板，写入报告作为"双端优化"的课程设计说明。 |
| 4 | **ChatQA** | 其"对话式 RAG"可落地：在 Streamlit 页面增加**多轮对话记忆**，将历史问答作为上下文传入下一轮检索和生成，支持追问场景。 |
| 6 | **CoRAG** | 其"拒绝采样生成检索链"可简化为：对同一问题生成 5 次答案，用**投票机制**选最一致的答案，记录 5 次的检索路径差异，作为系统稳定性的分析材料。 |

### 图增强 RAG 类

| # | 论文 | 项目改进建议 |
|---|------|-------------|
| 8 | **GraphRAG** | 其"知识图谱+社区摘要"可简化为：从知识库文档中用**正则+规则**抽取实体和关系，构建 JSON 格式的知识图谱，在 `rag_chain.py` 中增加图谱检索路径，作为混合检索的第三路信号。 |
| 9 | **LightRAG** | 其"双层检索"可落地：在现有 `hybrid` 检索基础上增加**实体级检索**——先用 NER 提取问题中的实体，在知识库中按实体名精确匹配，与向量/TF-IDF 分数三路加权融合。 |
| 11 | **RAS** | 其"动态构建问题特定知识图谱"可落地：对每个问题，先用 LLM 提取关键实体和关系，构建**问题级子图**，用子图辅助检索和推理，记录子图大小与答案质量的关系。 |

### 综述类

| # | 论文 | 项目改进建议 |
|---|------|-------------|
| 12 | **RAG Survey (Gao)** | 建议在报告中引用该综述的 **Naive→Advanced→Modal RAG** 分类框架，将你的项目定位为 Advanced RAG（混合检索+Prompt 约束），并说明向 Modal RAG 演进的路线图。 |
| 13 | **RAG Survey (AIGC)** | 其"四类检索融合"分类法可作为报告的**理论框架**——你的 `hybrid` 检索属于 query-based 融合，可讨论如何扩展到 logits-based（模型输出层融合）。 |
| 14 | **RAG Meets LLMs** | 建议在报告中用其**架构-训练-应用**三维框架组织内容，将现有实验映射到这三个维度，提升报告的学术规范性。 |
| 15 | **RAG for NLP** | 其"教程代码"可直接参考，对比其检索实现与你的 `build_kb.py` 差异，在报告中讨论**轻量实现 vs 工业实现**的权衡。 |
| 16 | **Systematic Lit Review** | 其"PRISMA 方法论"可借鉴：对 Paper.md 中的 40 篇论文做**系统分类统计**（按方法、按会议、按年份），作为报告的相关工作综述图表。 |
| 17 | **RAG: Architectures & Robustness** | 其"robustness 分类"可落地：在评测中增加**对抗性测试**——故意提问与知识库无关的问题，检查系统是否正确拒答，统计拒答准确率。 |
| 18 | **Agentic RAG Survey** | 其"三阶段框架"可作为报告的**技术路线图**——说明当前项目处于 Reasoning-Enhanced RAG 阶段，未来可向 RAG-Enhanced Reasoning 演进。 |

## 三、优先级建议（最值得落地的 5 项）

| 优先级 | 改进项 | 借鉴论文 | 涉及文件 | 预期效果 |
|:---:|--------|---------|---------|---------|
| ⭐1 | **自适应检索循环**：答案置信度低时自动触发二次检索 | R-Search #3、ReaLM-Retrieve #8 | `src/rag_chain.py` | 提升难问题的检索命中率 |
| ⭐2 | **忠实度 NLI 检测**：用 NLI 模型验证答案是否被检索片段支持 | Self-Correcting RAG #16 | `src/eval.py` 新增指标 | 增加评测学术深度，降低幻觉 |
| ⭐3 | **分步推理 Prompt**：要求模型分步推理并标注引用来源 | ProRAG #5、Self-RAG #1 | `src/rag_chain.py` Prompt 部分 | 量化推理忠实度，答案更可追溯 |
| ⭐4 | **对抗性拒答测试**：增加无关问题检查系统拒答准确率 | RAG: Architectures & Robustness #17 | `eval_questions.csv` + `src/eval.py` | 补齐鲁棒性评测维度 |
| ⭐5 | **检索粒度多模式切换**：关键词/语义/全文三种模式可视化对比 | A-RAG #13、RankRAG #2 | `src/config.py` + `src/app.py` | Streamlit 页面功能增强 |

## 四、实施约束

- **无需引入 LangChain 或 ChromaDB**：所有建议均可通过修改 `src/` 下现有模块实现，保持项目依赖轻量。
- **无需微调模型**：所有改进均在 Prompt 层面、检索策略层面或评测指标层面，不涉及模型训练。
- **增量实施**：每项改进独立可测，可逐个添加并在 `results/` 中输出对比结果。
